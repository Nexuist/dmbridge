---
title: Instagram
description: Prepare an Instagram professional account and connect it to dmbridge.
---

Instagram's messaging API requires a professional account and a Meta developer
app. Start by creating an Instagram
[Creator account](https://help.instagram.com/2358103564437429) or
[Business account](https://help.instagram.com/502981923235522). Then
[register as a Meta developer](https://developers.facebook.com/docs/development/register/),
[create a Meta app](https://developers.facebook.com/docs/development/create-an-app/),
and follow Meta's
[Instagram API setup](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/get-started/)
to obtain an access token.

## What you need

| Value | Required? | What to enter |
| --- | --- | --- |
| Account name | Yes | A local dmbridge label for this login. The setup script defaults to `personal`. |
| Access token (`accessToken`) | Yes | An Instagram user access token issued for the professional account by your Meta app. |
| Account ID (`accountID`) | No | An optional known Instagram account ID. dmbridge discovers it from `/me` when omitted. |
| Account username (`accountUsername`) | No | An optional known Instagram username. dmbridge discovers it from `/me` when omitted. |
| Graph API version (`apiVersion`) | No | An optional version such as `v24.0`. Omit it to use the unversioned `graph.instagram.com` endpoint. |

dmbridge does not ask for your Meta app ID, app secret, or OAuth redirect URI.
Those may be part of issuing the access token in Meta's developer tools, but
dmbridge only needs the resulting token. The guided script asks only for the
account name and access token; the other optional fields are available through
the structured `accounts add instagram` request.

From a dmbridge repository checkout:

```sh
./scripts/connect-ig.sh
```

The script asks for the account name, optional dmbridge home, and access token
one line at a time. The token is hidden while you type and passed to dmbridge
through a temporary mode-`0600` file.

The script is safe to rerun. Replacing an existing authorization requires
explicit confirmation.
