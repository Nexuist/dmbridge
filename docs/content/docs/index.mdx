dmbridge gives scripts and AI agents one predictable JSON interface for direct
messages across XChat and Instagram Messaging. It is free and open source, runs
entirely on your machine, and talks directly to each platform. There is no
dmbridge-hosted middleman service or subscription.

## Why it exists

[twocents](https://twocents.com) runs a lot of social media accounts. We wanted
one practical way for our agents to handle incoming messages without teaching
each agent a different API, authentication flow, and response format.

So we built dmbridge.

## How it was built

dmbridge was vibe coded with Codex and GPT-5.6 against those real workflows.
The speed came from the model; confidence comes from tests that pin down the
behavior. The offline test suite covers authentication, schemas, pagination,
provider fixtures, encryption paths, mutations, attachments, and failure
behavior. An optional live, read-only suite can verify configured X and
Instagram accounts.

You should still review what your agent intends to do. Every mutation supports
`--dry-run`, destructive actions require confirmation, and failures report
whether an automatic retry would be safe.

## What works

- XChat and Instagram Messaging
- Multiple named accounts per platform
- Direct and group conversations where the provider supports them
- Conversation and message-request inboxes
- Read, send, reply, edit, delete, and read-state operations where supported
- Reactions and attachment downloads
- JSON output with stable, versioned schemas
- Non-interactive operation for agents and scripts

Provider APIs can change underneath dmbridge. Use `doctor --live` when you want
to verify a configured account against the real provider.

## The contract

- Primary results are JSON on stdout.
- Progress, warnings, and diagnostics go to stderr.
- Every envelope has a stable protocol version.
- Every mutation supports `--dry-run`.
- Destructive actions require explicit confirmation.
- Errors say whether an automatic retry is safe.
